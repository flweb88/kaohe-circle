# 考核小管家 MVP-5 · Mac 侧媒体压缩工人 — 使用说明

> 本交付物把「用户上传的大图片/大视频」从 NAS 拉到 Mac 本地压缩，再回传落位。
> 本期**只交付文件，不部署、不注册 launchd、不安装软件、不改线上**。下面的安装/配置均为部署期（后续）动作。

| 文件 | 位置 | 作用 |

| 压缩工人脚本 | `/Volumes/no2/项目/豆包/考核网站/考核小管家/scripts/kaohe-worker.sh` | Mac 侧执行，单轮：拉取→压缩→回传→落位→清理 |
| launchd 模板 | `/Volumes/no2/项目/豆包/考核网站/考核小管家/scripts/com.kaohe.worker.plist` | 每 45s 触发一轮（方案要求 30~60s） |
| NAS 落位工具 | `/Volumes/no2/项目/豆包/考核网站/考核小管家/kaohe-api/manifest_tool.php` | SSH 调用：校验产物、移入正式区、更新 manifest、pending→done、孤儿清理 |
| 本说明 | `/Volumes/no2/项目/豆包/考核网站/考核小管家/scripts/使用说明.md` | 安装/依赖/部署配置项/排障 |

> 说明：`manifest_tool.php` 按要求放在源码库 `kaohe-api/` 下（与 `common.php` 同目录，部署时随之一并 scp 到 NAS `/var/services/web/kaohe-api/`），**不入 `deploy.sh` 白名单**，仅 SSH CLI 调用，脚本内已加 `php_sapi_name()!=='cli' → 403` 守卫，web 访问不可执行。

## 2. 架构一句话

用户上传 → NAS `uploads/_pending/{id}.{ext}` + manifest(pending) → Mac 工人每轮经 ssh 列目录并 `ssh 'cat remote' > 本地` 拉到 `~/.cache/kaohe-worker` → sips/ffmpeg 压缩 → `ssh 'cat > remote' < 本地` 回传 `uploads/_incoming/{id}/` → ssh 跑 `manifest_tool.php` 校验落位、manifest 置 ready、pending 移入 `done/`（压缩视频原片直接删除）。

> **传输方式实测结论**：本环境群晖 sshd 拒绝执行 `rsync --server`（rsync 二进制虽在，但 over-ssh 通道被封，实测 `Permission denied`），故工人采用 deploy.sh 同款的 ssh 原始二进制管道（`cat`），非 base64/scp/sftp。2MB 随机文件往返实测字节一致。

## 3. 安装步骤（部署期执行，本期不做）

1. **脚本安装**
   ```bash
   mkdir -p ~/.local/bin ~/.local/log ~/.cache/kaohe-worker
   cp scripts/kaohe-worker.sh ~/.local/bin/kaohe-worker.sh
   chmod +x ~/.local/bin/kaohe-worker.sh
   ```
2. **manifest_tool.php 上 NAS**（不入 deploy 白名单，手动一次）
   ```bash
   ssh "$KAOHE_NAS" 'cat > /var/services/web/kaohe-api/manifest_tool.php'  # KAOHE_NAS 如 用户@NAS主机，仅本地配置 \
     < kaohe-api/manifest_tool.php
   ```
3. **配置（可选）**：`~/.config/kaohe-worker.conf` 里覆盖任意常量，例如
   `KAOHE_FFMPEG=$HOME/.local/bin/ffmpeg`、`KAOHE_NAS_UPLOADS=...`。
4. **手动试跑**：`bash ~/.local/bin/kaohe-worker.sh`（正常无输出；细节看 `~/.local/log/kaohe-worker.log`）。
5. **注册 launchd**：
   ```bash
   # 先按 plist 内注释把三个 /Users/fangliang 路径改成实际 home
   cp scripts/com.kaohe.worker.plist ~/Library/LaunchAgents/
   launchctl load ~/Library/LaunchAgents/com.kaohe.worker.plist
   # 立即跑一轮： launchctl start com.kaohe.worker
   # 卸载：     launchctl unload ~/Library/LaunchAgents/com.kaohe.worker.plist
   ```

## 4. 依赖

| 依赖 | 状态 | 说明 |
|---|---|---|
| `sips` (`/usr/bin/sips`) | macOS 自带，已核实 | 图片缩放/缩略图，无需安装 |
| `ssh`（+ `cat` 管道） | macOS 自带 | 唯一传输通道；rsync over ssh 被 NAS sshd 封禁，实测不可用 |
| **`ffmpeg`** | **已装 `~/.local/bin/ffmpeg` v6.0 arm64（含 libx264）** | 用于 >50MB 视频压 720p；脚本 `KAOHE_FFMPEG` 已指向它 |

**ffmpeg 获取方式（二选一），脚本用 `FFMPEG_BIN` 定位：**
- 推荐：下载 macOS 静态构建（如 evermeet.cx 的 ffmpeg .release.7z）解压后放到 `~/.local/bin/ffmpeg`，并在 `~/.config/kaohe-worker.conf` 写 `KAOHE_FFMPEG=$HOME/.local/bin/ffmpeg`。
- 或：装 Homebrew 后 `brew install ffmpeg`（脚本会自动 PATH 探测到）。
- 当前本机已装 `~/.local/bin/ffmpeg` v6.0（含 libx264），`KAOHE_FFMPEG` 已指向它；若日后该二进制缺失，>50MB 视频会被标 `failed`（failReason=`ffmpeg_missing`），不影响其他媒体。

> 注意：NAS 自带 `/usr/bin/ffmpeg` 是裁剪版（无 H.264 编解码），不可用，故压缩必须在 Mac 侧做。

### 周三停机窗口（运维事实）
NAS **每周三 01:30–08:00 停机维护**。该窗口内 SSH 必然失败：工人会**指数退避静默重试**（30s 起步、逐次翻倍、上限 5 分钟一次），**不崩溃、不刷错误日志**（每轮只写一行 backoff 记录到滚动日志，stdout 静默）；NAS 恢复后自动复位并续处理。该窗口上传接口本身也不可用，前端按既有网络错误态展示即可。

## 6. 压缩与清理规则

- 图片：`>3MB` → `sips -Z 1080` 生成 orig（最大边 1080p）；`≤3MB` → 原图即 orig；所有图片派生 `sm`(360px) / `md`(720px) 两份 jpg（质量 82）。
- 视频：`>50MB` → ffmpeg `scale=-2:720` H.264/aac，产物 `{id}.720.mp4` 为**唯一播放版**，原视频**不保留**（Mac 缓存不留、NAS 正式区不存、原 pending 直接删除，manifest 只记 `video720`，前端直接播 720p，无"点原图"路径）；`≤50MB` 原样回传（manifest 记 `orig`）。
- 音频：不压缩，原样。
- Mac 缓存目录 `~/.cache/kaohe-worker`：**每批结束即清空**；硬上限 **5GB**，超限按 mtime 先删最旧。
- NAS 孤儿清理（工人每轮顺手调 `--sweep`）：`_pending/` 超 7 天 → manifest 标 failed 并删文件；`done/` 超 30 天 → 删除。压缩成功的 >50MB 视频原片**不进 done/**，落位时即直接删除（省 NAS 磁盘）。
- 删帖清理：由后端 `social.php?action=del` 负责软删帖子 + 物理删除关联 `{id}.*` + 移除 manifest 记录（不在本脚本范围）。

## 7. 安全

- 传输仅 `ssh` 密钥 + 原始二进制 `cat` 管道（已实测 2MB 往返字节一致）；**禁用 scp/sftp/base64 管道传大文件**。
- 产物回传前在 Mac 侧用 `file(1)` 复核 MIME；NAS 侧 `manifest_tool.php` 再用 `finfo` + 扩展名白名单双校验，**通过才落 uploads/ 正式区**；不通过 → manifest 标 `failed`、不落正式区、清 `_incoming`。
- `manifest_tool.php` 仅 CLI（web 请求 403）；id 限 hex；所有路径 basename 防穿越。

## 8. 故障排查

| 现象 | 排查 |
|---|---|
| 上传后一直“处理中…” | 看 Mac 在线？`bash ~/.local/bin/kaohe-worker.sh` 手动跑一轮；看 `~/.local/log/kaohe-worker.log` |
| 视频显示“处理失败”、failReason=`ffmpeg_missing` | 装 ffmpeg（§4），让用户重发该视频 |
| `manifest nonzero` / `busy` | NAS manifest.php 锁竞争或不可写，下一轮自动重试；持续出现查 NAS 磁盘/权限 |
| 周三白天一直不处理 | 正常：01:30–08:00 停机窗口，退避静默，恢复后自动续 |
| 想确认退避状态 | `cat ~/.cache/kaohe-worker/.state/last_fail` 与 `streak` |
| launchd 没跑 | `launchctl list | grep kaohe`；看 `~/Library/LaunchAgents/...plist` 路径是否改对、日志 `kaohe-worker.err.log` |
